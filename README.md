# OzonHW3

Два простых Go-сервиса: каталог товаров по gRPC и корзина по HTTP.

## API first

Сначала описаны контракты:
- `api/product/v1/product.proto` — gRPC API. Из него сгенерированы `product.pb.go` и `product_grpc.pb.go`.
- `api/cart.yaml` — OpenAPI-контракт HTTP API. Обработчики написаны вручную на `net/http`.

При изменении API сначала измените контракт, затем реализацию и тесты.

## Структура

- `cmd/product-service` и `cmd/cart` — запуск сервисов.
- `internal/product` — загрузка JSON и метод GetProduct.
- `internal/cart` — HTTP-обработчики и корзины в памяти.
- `products.json` — пример каталога товаров.

Каталог после загрузки только читается. Корзины хранятся в памяти под `sync.RWMutex`. Счётчик успешных добавлений в сервисе корзины обновляется через `atomic.Uint64`; количество товара изменяется под блокировкой корзины. При чтении корзины сведения о товарах запрашиваются параллельно с общим таймаутом 3 секунды.

## Запуск

Нужен Go 1.27 или новее в PATH:

```sh
go mod download
make run-all
```

Каталог слушает `:50051`, корзина — `:8080`. Ctrl+C останавливает оба процесса. Команду запускайте из корня проекта. Сгенерированные Go-файлы включены, поэтому protoc для запуска не нужен.

Если Go установлен только через GoLand:

```sh
make run-all GO="$HOME/sdk/go1.27.1/bin/go"
```

Отдельный запуск:

```sh
go run ./cmd/product-service
go run ./cmd/cart
```

## Проверка API

```sh
curl -i -X POST localhost:8080/user/1/cart/2958025 \
  -H 'Content-Type: application/json' -d '{"count":2}'
curl -i localhost:8080/user/1/cart
```

POST возвращает 204 без тела. Повторное добавление увеличивает количество. GET запрашивает актуальные название и цену у каталога, сортирует позиции по SKU, считает сумму price × count. Пустая корзина — 404, неверные параметры — 400, отсутствующий товар при добавлении или чтении — 412, сбой gRPC — 500. Переполнение количества — 400, итоговой стоимости — 500.

Цена в protobuf — int32, внутри сервисов — uint32. При загрузке каталог проверяется на совместимость с int32. После перезапуска корзины теряются, каталог загружается заново.

## Генерация и тесты

Для генерации установите protoc, например `brew install protobuf` на macOS, затем:

```sh
make generate
make test
make test-race
make bench
```

`make generate` устанавливает генераторы фиксированных версий в локальный `bin/`. `make test` запускает юнит-тесты, `make test-race` включает детектор гонок и дополнительные конкурентные тесты. Интеграционный тест запускается отдельно: сначала `make run-all`, затем `make test-api` в другом терминале. `make bench` запускает бенчмарки с измерением аллокаций.

Цена синхронизации (Apple M1 Pro, три прогона с `-benchmem`; приведена медиана):

| Бенчмарк | Без `RWMutex`, ns/op | Без `RWMutex`, allocs/op | С `RWMutex`, ns/op | С `RWMutex`, allocs/op |
| --- | ---: | ---: | ---: | ---: |
| `BenchmarkAddToCart` | 2382 | 26 | 2395 | 26 |
| `BenchmarkGetCart` | 4623 | 38 | 4544 | 38 |

Вариант «без `RWMutex`» воспроизведён в отдельной временной копии текущего кода с удалёнными только блокировками. Это замер без конкурентной нагрузки; разница находится в пределах разброса прогонов и не доказывает ускорение чтения. Race-тест на этой копии обнаружил `DATA RACE` и потерю добавлений, а на рабочем коде проходит.

Реализовано основное задание. Дополнительные ListProducts, middleware логирования и Swagger UI не добавлены; HTTP-контракт доступен в `api/cart.yaml`.
